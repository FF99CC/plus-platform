# 业务说明

## 账号

| 初始账号 | 用途 |
|---|---|
| `test` | 业务员，办理自己的项目 |
| `test1` | 审批负责人，查看全部项目并审批申请 |
| `admin` | 管理人员、部门、角色和审批设置 |

运行 `python3 dev.py credentials` 查看初始密码。管理员也需要被指定为当前审批人，才能办理审批。

## 办理流程

直接委托：

项目办理 → 新建备案，选择“直接委托” → 备案审批通过 → 填写施工立项 → 立项审批通过。

参与投标：

新建备案，选择“参与投标” → 备案审批通过 → 投标申请审批通过 → 投标准备（按需登记）→ 登记开标结果 → 中标后填写立项 → 立项审批通过。

项目详情会显示当前阶段、下一步、申请和跟进记录。
审批负责人在“待我审批”查看申请，选择通过或退回。

- 退回时必须填写意见；经办人修改后重新提交，原审批记录保留。
- 审批中不能修改申请内容。
- 未中标或已终止的项目不能立项；已立项的项目不能重复提交立项。

## 调整审批流程

管理员进入“审批设置 → 审批流程”，在已发布流程上点击“修改流程”，复制成草稿后进入“流程设计”。

1. 在“条件与审批人”中，选择承接方式、发起部门、金额等分支条件，并配置各步骤的审批人。
2. 需要新增审批步骤、增加分支或调整顺序时，打开“流程图”，保存后返回中文配置。
3. 保存配置，在“审批路线预览”中选择发起人、填写模拟申请资料，检查路线和审批人员。
4. 确认后到草稿列表发布。预览不会创建申请，也不会代替发布操作。

- 新申请使用新发布版本；已提交申请继续使用原来的版本。
- 选中的审批人员需要同时具有项目查看和审批权限；也可以在节点中选择角色、部门或岗位。
- “发起部门负责人”取本次提交人的所在部门负责人，请先在“管理设置 → 部门组织”中设置。“部门成员”表示该部门的人员。
- “发起部门”等于所选部门时只匹配该部门，不自动包含下级部门。部门和承接方式需要同时判断时，可以在流程图中分两层设置分支。
- 待我审批只显示当前分配给自己的申请；全部审批环节通过后，项目才进入下一阶段。
- 流程至少保留一个人工审核环节。任意环节退回后，经办人修改并重新提交，重新开始一次审批。

例如，备案按承接方式分成两条路径；投标路径再按发起部门分流，交给各部门负责人审批。

预览表示当前资料下后续全部同意时的预计路线，支持串行审批和互斥条件分支。没有匹配路线、缺少审批人或部门负责人时会提示；并行、特殊表达式和自定义监听器等暂不能完整预览，不会按成功展示。高级配置仍在流程图中维护。

## 演示数据

服务启动后运行 `python3 dev.py demo`，添加虚构的启明建设集团：总部、华东、华南三家公司，各设市场、工程、投标、财务、综合五个部门，共 49 个账号。公司作为组织树中的节点使用；目前不代表独立租户或公司间的数据隔离。

运行 `python3 dev.py credentials --demo` 查看账号和初始密码。经办人只能办理自己的项目；有审批权限的人员可查看全部项目，但只能审批实际分配给自己的申请。

| 演示账号 | 用途 |
|---|---|
| `demo_hq_market_01` | 总部市场经办人 |
| `demo_hq_market_lead` | 总部市场负责人，也可发起申请 |
| `demo_hq_engineering_01` | 总部工程经办人 |
| `demo_east_market_01`、`demo_south_market_01` | 华东、华南市场经办人 |
| `demo_hq_bid_lead` | 集团投标专员 |
| `demo_hq_finance_lead` | 集团财务复核 |
| `demo_general_manager` | 集团总经理 |

管理员在“审批设置 → 审批流程”的草稿列表查看名称以“[演示模板]”开头的流程：

| 模板 | 分支示例 |
|---|---|
| 备案·承接方式 | 直接委托由部门负责人审批；参与投标先投标专员，再部门负责人 |
| 备案·金额分级 | 预计金额不超过 100 万元由部门负责人审批；超过时增加财务、总经理 |
| 备案·发起部门 | 市场、工程及其他部门走不同审批路线，负责人取发起人所在部门 |
| 备案·指定发起人 | 总部市场负责人发起时直接交总经理，其他人交部门负责人 |
| 立项·金额分级 | 立项金额不超过 500 万元由部门负责人审批；超过时增加财务、总经理 |

这些门槛和人员安排只是可修改的例子。流程页面的金额输入单位为**元**，100 万元填写 `1000000`。

先打开模板做“审批路线预览”，选择上表账号和模拟资料。实际办理时，发布需要的模板，再用对应经办账号新建申请；同一类业务同时只使用一个已发布版本，已提交申请继续原版本。测试金额模板时可分别输入 `1000000` 和 `1000000.01`，检查边界。

初始化不修改原有账号、组织或已发布流程。重复运行只补齐未完成的创建，不覆盖手工改名、改密或流程调整；保留 `.runtime/demo-data.json`，它保存本环境的演示记录和初始密码，不提交 Git。

## 功能范围

初始流程仍由一名审批负责人办理。实际审批岗位、条件和项目查看范围需要业务方确认。

标书、借证、用章、保证金目前只登记准备事项、负责人姓名和完成情况，不包含任务分派、证书调配、盖章或收付款。

尚未提供附件上传、合同、成本、采购、款票、审定等后续功能，也未迁移旧数据。
